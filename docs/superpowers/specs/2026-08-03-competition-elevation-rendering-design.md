# Competition Elevation Rendering Design

**Date:** 2026-08-03  
**Status:** Proposed for implementation  
**Scope:** Exact-MASS competition elevations first; presentation axon second

## 1. Objective

Produce competition-board-quality architectural elevations from the selected enriched GLB while preserving the exact MASS geometry and measurable dimensions. The elevations must read as drawings rather than raw viewport captures: orthographic, uncropped, materially legible, dimensioned from authoritative geometry, and visually restrained. After the elevation pipeline passes, reuse the same material system for a higher-quality competition-style axon render.

The implementation keeps one geometry source. Material styling, drawing annotations, and camera presentation may vary, but every view and every dimension remains bound to the selected GLB and source candidate hashes.

## 2. Delivery Order

1. Complete and approve `front` elevation.
2. Apply the same verified rules to `back`, `left`, and `right`.
3. Refine `plan` and `top` as separate drawing modes.
4. Produce the competition-style presentation `axon`.

No later stage may weaken the geometry, provenance, or dimension gates established by the front elevation.

## 3. Authoritative Geometry and Dimension Contract

Dimensions are never inferred from the approved image or generated by an image model. Sources, in descending authority, are:

1. Parsed selected-GLB `exact-mass` position and index accessors.
2. Candidate indexed mesh and manifest hashes.
3. `facade_planes.facade_planes` origins, normals, horizontal axes, and extents.
4. `floor_guides.floor_guides_m` authored elevations.
5. Parsed semantic detail geometry for secondary opening/frame dimensions.

The dimension engine produces a versioned manifest containing the selected GLB SHA-256, candidate geometry hash, source field for every value, value in metres, displayed millimetres, view, projected endpoints, and tolerance.

### Required dimensions

- Overall projected width for each elevation.
- Exact overall MASS height.
- Every authored floor-to-floor interval and cumulative level.
- Authored facade extent where it differs from overall projected width.
- Major terminal-block width/height when it is a distinct connected projected region.
- Scale bar derived from orthographic world-to-pixel mapping.

Opening, mullion, or panel dimensions are shown only when actual semantic geometry supports them. No repeated bay dimension is printed when clipped curved geometry makes the repetition nonuniform.

### Display convention

- Default dimension unit: millimetres, unit omitted on individual dimension labels.
- Drawing note: `ALL DIMENSIONS IN MILLIMETRES`.
- Level markers retain metres with three decimals, for example `EL. +3.300`.
- Numerical agreement tolerance: 1 mm for annotations; canonical Float32 tolerance remains as defined by strict geometry validation.

## 4. Elevation Camera and Composition

Each elevation uses the authoritative source projection axes and an orthographic camera. After the GLB loads, all eight world-bounds corners are projected into the view plane. The camera is fitted to those real projected bounds, not stale input image bounds.

- Content margin: 8–10% on all sides before the annotation band.
- No perspective convergence.
- Building vertical axis aligned to image vertical.
- Ground datum horizontal.
- Annotation band reserved below and beside the building so dimensions never cover geometry.
- Default output: 2400 × 2400 PNG plus a vector-capable SVG annotation overlay/manifest.

## 5. Competition Elevation Render Stack

The elevation is assembled from independent passes:

1. **Material fill pass:** flat-to-soft PBR colours with restrained directional light.
2. **Depth silhouette pass:** screen-space depth boundaries; coplanar source-triangle seams are excluded.
3. **Semantic line pass:** parapets and slab/frame bands heavy, opening frames medium, mullions light.
4. **Soft shade pass:** weak sun/ambient modulation only; no dramatic perspective shadow.
5. **Annotation pass:** ground line, level markers, dimensions, title, orientation, scale bar.

Line hierarchy target at final resolution:

- External silhouette and cut/ground line: 2.0–2.4 px.
- Major slab/parapet/frame boundary: 1.2–1.6 px.
- Opening frame: 0.8–1.0 px.
- Mullion and secondary detail: 0.5–0.7 px.
- Dimension/level guides: 0.45–0.6 px.

Internal triangulation and per-primitive borders must never appear merely because the enriched surface was clipped per source triangle.

## 6. Material Palette System

Geometry semantics and material appearance are separated. A palette maps the stable semantic roles `concrete`, `glass`, `bronze`, and `opaque` to rendering parameters without changing geometry.

Each palette may configure:

- Base colour and tint.
- Roughness and metalness.
- Opacity/transmission and glass reflectivity.
- Subtle texture scale and normal intensity.
- Elevation fill colour.
- Axon PBR colour.
- Line contrast and shadow strength.

Initial presets:

1. `competition-warm`: warm off-white concrete, blue-grey glass, dark bronze mullions, charcoal opaque panels.
2. `competition-neutral`: neutral concrete, desaturated glass, graphite metal.
3. `competition-stone`: pale stone/concrete frame, darker recessed glass, champagne-bronze accents.

The selected preset and complete resolved values are saved in the run/version manifest. Future palettes can be added as JSON without modifying geometry code. Validation requires all semantic roles to remain mapped and prevents invisible or fully transparent structural roles.

## 7. Competition Axon Stage

After all elevations pass, the axon renderer uses the same selected GLB and chosen palette with a separate presentation configuration:

- Mild perspective camera rather than the elevation orthographic camera.
- Whole-building fit with intentional white-space composition.
- Environment illumination, soft sun, contact shadow, and ground plane.
- Controlled glass reflection and concrete texture.
- Minimal scale figures and trees placed outside the authoritative building geometry.
- Context assets recorded separately and excluded from MASS geometry/dimension validation.

This stage must not replace the GLB with an image-generated mesh.

## 8. Interfaces and Artifacts

New or extended interfaces:

- `resolveMaterialPalette(presetOrOverrides): ResolvedPalette`
- `deriveElevationDimensions({ sourceMesh, artifact, facadePlanes, floorGuides, view }): DimensionManifest`
- `renderCompetitionElevation({ glbPath, view, camera, palette, dimensions, outputDir, signal }): ElevationArtifacts`
- `validateCompetitionElevation({ image, lineManifest, dimensionManifest, geometry, provenance }): ValidationReport`

Per-view artifacts:

- `<view>.png`
- `<view>-annotations.svg`
- `<view>-dimensions.json`
- `<view>-render-manifest.json`

The run-level provenance binds every artifact to the selected GLB SHA, viewer/render configuration SHA, palette SHA, and dimension-manifest SHA.

## 9. Validation and Failure Codes

Required gates:

- `ELEVATION_CAMERA_NOT_ORTHOGRAPHIC`
- `ELEVATION_AXIS_MISMATCH`
- `ELEVATION_CONTENT_CLIPPED`
- `DIMENSION_SOURCE_MISSING`
- `DIMENSION_MISMATCH`
- `LEVEL_GUIDE_MISMATCH`
- `MATERIAL_ROLE_MISSING`
- `MATERIAL_VISIBILITY_INVALID`
- `LINE_DENSITY_EXCEEDED`
- `TRIANGULATION_VISIBLE`
- Existing GLB, exact-base, drawing decode, hash, provenance, and component gates remain mandatory.

Generated visual failures may use the existing one-retry state machine. Geometry/hash/input failures remain blocked. The retry may change camera fit, line thresholds, or palette visibility, but never dimension values or source geometry.

## 10. Test Strategy

- Unit tests for projected bounds, metre-to-millimetre conversion, level chains, scale bar, and palette resolution.
- Adversarial tests for stale camera bounds, clipped terminal blocks, wrong facade axes, tampered dimension values, missing palette roles, transparent structure, and visible triangle seams.
- Pixel/manifest tests proving material fills differ while dimension values and silhouettes stay invariant across presets.
- Real `creative-013` front elevation first, checked against source dimensions: overall height 9.900 m and floor guides 0.000/3.300/6.600/9.900 m.
- After front approval, run all four elevations and confirm matching level locations and a single selected-GLB provenance chain.

## 11. Acceptance Criteria

The front elevation is accepted when:

- The whole building is visible with 8–10% composition margin.
- It is visibly orthographic and vertically aligned.
- Triangle clipping seams are absent.
- Concrete, glass, bronze, and opaque roles remain distinguishable at presentation scale.
- Overall and level dimensions equal authoritative MASS values within 1 mm.
- Dimension lines and labels do not overlap the building.
- The image reads as a competition elevation rather than a raw viewport screenshot.
- Strict geometry, image decoding, hash, and provenance validation passes.

Only then are the remaining elevations and axon stage implemented.

## 12. Reference Direction

Competition representation is treated as an argument combining visual atmosphere with legible drawings, line work, colour balance, and layout. The delivery therefore separates a materially expressive elevation/axon render from accurate dimension and line information while binding both to one selected GLB.
